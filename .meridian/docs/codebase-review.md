## What this project is — purpose and domain, in the project's own terms

Meridian (`@knowalabs/meridian`) is a CLI that makes *other* codebases "AI-assistant-ready" in one command. Its own words, from README.md: "One command to set up every AI coding tool on any machine." It is not an application with end-user features in the usual sense — it is a meta-tool for the AI-coding-tool ecosystem: it reads a target project, has a configured AI provider write a deep review of it, and then generates the artifacts every AI coding assistant needs to work well in that project — canonical rules mirrored into `CLAUDE.md`, `AGENTS.md`, `GEMINI.md`, `.cursor/rules/meridian.mdc` and `.github/copilot-instructions.md`, plus Claude Code subagents, skills, slash commands, a permissions harness (`.claude/settings.json`), reusable prompts, and a `docs/` suite (README.md, CHANGELOG.md "0.1.0" section).

Around that central `generate`/`sync` capability sit the supporting concerns a CLI like this needs: a router across a dozen AI providers (`src/providers/router.ts`), a cross-platform secret vault (`src/core/vault.ts`), an MCP-server marketplace/installer (`src/mcp/`), and an installer/updater for the AI tool CLIs themselves (`src/plugins/tools.ts`, `src/commands/install.ts`). The domain is squarely "developer tooling for developer tooling" — it explicitly supports non-Node ecosystems (Rust, Go, Python, Java/Kotlin/Scala, Ruby, PHP, .NET, Elixir, Swift, Dart/Flutter, Deno) because its own target audience is any codebase, not just JS/TS projects.

## Architecture

- **`src/index.ts`** — process entrypoint. Checks Node ≥ 18, installs global `uncaughtException`/`unhandledRejection`/`SIGINT` handlers that funnel into `renderError`, and dispatches to either the interactive launcher (bare invocation in a TTY) or `buildCli().parseAsync()`.
- **`src/cli.ts`** — the single Commander command tree (`buildCli`): `doctor`, `install`/`uninstall`, `auth`/`keys`, `generate`, `sync`, `mcp` (search/install/remove/list), `ask`, `router`, `update`, `login`. Global flags (`--verbose`, `--quiet`, `--json`, `--no-color`) are attached recursively via `addGlobalFlags` so they work on every subcommand.
- **`src/launcher.ts`** — the interactive TUI (`runInteractive`/`menuPrompt`) shown for a bare `meridian` in a terminal: arrow-key menu with live text filtering, raw commands typed straight through, banner rendering (`showBanner`/`bannerRows`). Commands run in-process via `buildCli({ exitOverride: true })` so a failing command never kills the menu loop.
- **`src/commands/*`** — one thin orchestration module per command group (`ask.ts`, `auth.ts`, `doctor.ts`, `generate.ts`, `install.ts`, `mcp.ts`, `sync.ts`, `update.ts`). These parse/validate flags, call into `core`/`generate`/`providers`, and format output (respecting `--json`/`log`).
- **`src/core/*`** — cross-cutting infrastructure: `config.ts` (global `~/.meridian/config.json` load/save with `coerceConfig` validation), `errors.ts` (`CliError`, `EXIT` codes, `renderError`), `exec.ts` (subprocess helpers: `run`/`runAsync`/`runLive`/`which`), `fsx.ts` (atomic writes, backups, JSON reads), `logger.ts`, `paths.ts` (`meridianHome`), `plugin.ts` (`ToolPlugin`/`PluginRegistry` interface shared by installable tools), `prompt.ts` (interactive prompts, `didYouMean`), `vault.ts` (secret storage), `validate.ts` (config shape coercion).
- **`src/scan/*`** — read-only analysis of the *target* codebase: `analyzer.ts` (`analyzeProject` → `ProjectAnalysis`: languages, frameworks, scripts, conventions, API routes, code map), `git.ts` (`collectGitSignal`/`churnMap` — recent-activity signal), `ignore.ts` (gitignore-aware matcher shared by everything that walks the tree), `workspaces.ts` (monorepo detection for npm/yarn/pnpm/Lerna/Cargo/`go.work`).
- **`src/generate/*`** — the core pipeline: `digest.ts` (`buildDigest` turns a `ProjectAnalysis` + file excerpts into a budgeted text blob for the AI, plus the follow-up `` (`src/generate/artifacts.ts`) and `` (`src/generate/digest.ts`) work identically across hosted APIs and the three keyless CLI providers (`claude-code`, `codex-cli`, `gemini-cli`), which only expose a plain `ask(prompt)` string interface. "Upgrading" this to structured tool calls would break those three providers.
- **`isAllowedPath` (`src/generate/artifacts.ts`) is the sole boundary** preventing AI-suggested content from writing outside the target project (absolute paths, `..` escapes, Windows drive letters). `CODEOWNERS` and `SECURITY.md` both flag it by name; any new `ArtifactKind` or path-handling code must route through it.
- **Retry logic deliberately never retries a timeout**, only classified transient statuses/network errors (`src/providers/router.ts`'s `post`/`rawPost`) — retrying a hung provider would just multiply the wait, so a timeout maps straight to a `CliError` instead.
- **Cost estimation is honestly incomplete**: `MODEL_PRICING` (`src/providers/router.ts`) hardcodes exactly two models; everything else reports "unknown cost" from `--estimate` rather than a wrong number — correct behavior, but worth knowing before trusting the feature's output for an arbitrary provider/model.

## Maturity & gaps

Strong, above-average discipline for a pre-1.0 CLI:
- Strict TypeScript (`strict`, `noUncheckedIndexedAccess`, `noImplicitOverride`) plus type-aware ESLint with `no-explicit-any`/`no-floating-promises`/`no-misused-promises`.
- Three-OS × three-Node-version CI matrix on every push/PR, running lint, format-check, build, coverage-gated tests, and a full e2e subprocess suite (`.github/workflows/ci.yml`).
- A real `SECURITY.md` with a private-disclosure process, an explicit in-scope/out-of-scope boundary, and a supported-versions table.
- `CODEOWNERS` naming the specific security-critical files (`src/core/vault.ts`, `src/generate/artifacts.ts`, `.github/workflows/`, `SECURITY.md`).
- Provenance-signed npm publishing (`npm publish --provenance`), gated on the git tag matching `package.json`'s version — a real release-integrity check, not just a version bump.
- Changesets (`@changesets/cli`) for changelog discipline (`CHANGELOG.md` reads like a maintained, per-release document, not an afterthought).

Gaps visible in (or conspicuously absent from) the digest:
- **No dependency-vulnerability scanning step in CI** — no `npm audit`, no CodeQL, and `.github/dependabot.yml` exists in the layout but its contents weren't in the digest, so its actual scope is unverified from what's available.
- **Release-process fragility has already bitten this project once**: `CHANGELOG.md`'s 0.1.1 entry documents npm silently rewriting `bin.meridian` from `"./dist/index.js"` to `"dist/index.js"` during the 0.1.0 publish, disagreeing with the repository's own manifest — a concrete, recent incident, not a hypothetical.
- **Single-maintainer bus factor**: `CODEOWNERS` routes everything to one owner, and "Recent activity" reports 1 contributor over 67 commits in 180 days — normal for this stage, but real.
- **`--estimate`'s advertised value ("Knowing the cost before you spend it")** is undercut by only two providers having a built-in price table (`MODEL_PRICING` in `src/providers/router.ts`); the feature degrades gracefully but the marketing claim in README.md outruns the current data.
- **`meridian login`/Cloud Sync is a stub** (`loginCommand` in `src/commands/update.ts` just prints "not available yet") — openly a roadmap placeholder, not a hidden gap, but a real half-built surface a reader should not mistake for working.

## Trajectory

- **Multi-ecosystem breadth is a stated, active goal, not an afterthought.** `src/scan/analyzer.ts` and `src/generate/digest.ts` already detect and derive commands for Rust, Go, Python, Java/Kotlin/Scala, Ruby, PHP, .NET, Elixir, Swift, Dart/Flutter and Deno, and README.md leads with "Any stack, not just Node." Anything added to the generation pipeline should keep going through the same ecosystem-agnostic abstractions (`scriptRunner`/`commandFor` in `src/generate/artifacts.ts` and `src/scan/analyzer.ts`) rather than assuming npm.
- **The product has rebranded twice very recently** — "rename the product from DevPilot to Knowa" (2026-08-05) then "Rename product from Knowa to Meridian" (2026-08-24) — and just re-published under a brand-new npm scope, `@knowalabs/meridian`, restarting the version at 0.1.0 ("Republish as @knowalabs/meridian, starting from 0.1.0", 2026-09-04). Anything generated (docs, config, examples) should treat the product/package name and repo URL as unstable metadata likely to move again, not a hardcodable constant.
- **The `Rigor` dial and `residentCost` reporting** (`src/generate/artifacts.ts`, `src/generate/manifest.ts`) show the project moving from "dump a template" toward treating a generated kit as an ongoing cost/tradeoff surface with a persisted, non-silently-changing configuration. New artifact kinds should plug into both rather than reintroducing a flat, one-size-fits-all output.
- **`dependencyWaves`/`dependsOn` metadata** (`src/generate/pipeline.ts`, `src/generate/artifacts.ts`) anticipates a growing graph of artifact kinds that reference each other's output (commands delegating to skills today) — future kinds should declare dependencies through this mechanism rather than reaching into another kind's files directly.
- **The presence of `business/growth-plan.md`** alongside a marketing-restructured README (banner, badges, quickstart-first reorg per the 0.1.1 changelog entry) signals a shift from personal tool to a product with commercial intent; provenance-signed publishing and a real `SECURITY.md` are already in place to support that.
- **Cloud Sync is an explicit, named roadmap item** (`meridian login`, "sync encrypted API keys, rules, prompts, MCP config and preferences across machines" — `src/commands/update.ts`). This is almost certainly *why* keys are already behind a `Vault` interface with four interchangeable backends (`src/core/vault.ts`) rather than one hardcoded implementation — new work touching config, vault, or MCP storage should preserve that abstraction boundary rather than special-casing the local file layout.
