# Roadmap

Where `@sonalsithara/devpilot` has been and is headed, grounded entirely in `CHANGELOG.md`'s release history and the explicit `devpilot login` stub. Read this to understand why a module looks the way it does, or before adding something that conflicts with a direction already in motion. Not a wishlist — every entry below is evidence from a shipped release or a stated-but-unbuilt feature, never a speculative addition.

## Anticipated but not yet built

`devpilot login` (`src/commands/update.ts`'s `loginCommand`) and the README's "Cloud Sync (on the roadmap, not available yet)" are the one explicit stub in the codebase. Today `devpilot sync` is purely local and manifest-based (`.devpilot/manifest.json` on disk, diffed against a fresh `analyzeProject` call); Cloud Sync implies a future authenticated-account layer (team-shared kits, cross-machine state) that does not exist yet. New modules should not assume key/vault/config state is anything other than single-machine-local until this ships.

## Throughline

Four consecutive minor versions (0.12–0.15) converge on one idea: **the AI kit should behave like a build artifact** — reproducible (`manifest.json`), diffable (`diffFingerprints`), incrementally refreshable (`sync`), cost-estimable before running (`--estimate`), safe to regenerate without destroying hand edits (`fileStates`), and structurally consistent output (0.15's artifact contract). Workspace/monorepo support (0.13.0) is comparatively recent and still hardening — `src/scan/workspaces.ts` and `tests/workspaces.test.ts` cover the common cases (npm/yarn/pnpm/Lerna/Cargo/`go.work`), but nested or mixed-tool workspaces are not yet proven out.
