# Engineering standards

States the professional/enterprise bar this codebase's own tooling (Vitest, ESLint, GitHub Actions) makes possible, where the repo already meets it, and the concrete adoption step for each gap that remains — sourced from the Maturity & gaps section of `.devpilot/docs/codebase-review.md`. Read this when deciding whether a change needs a test, a CI step, or a doc update to hold the line. Not covered: standards for languages/stacks this repo doesn't use.

## Where the bar is already met

| Standard                                | Evidence                                                                                                                                                                                                                                                                                                                                          |
| --------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Broad, sandboxed test coverage          | 20+ files under `tests/*.test.ts` plus `tests/e2e/workflows.test.ts` (built-binary e2e: vault round-trip, corrupt-vault recovery, `generate` idempotency, `sync` drift/refresh/hand-edit preservation, MCP install/remove, `--quiet`/`--json` stream discipline). Sandboxed via `DEVPILOT_HOME`/`DEVPILOT_VAULT=file`, cleaned up in `afterEach`. |
| Numeric coverage gate, not aspirational | `vitest.config.ts`: 70% lines / 60% branches over `src/**/*.ts`, with a documented, deliberate exclusion for `src/launcher.ts` and `src/index.ts`.                                                                                                                                                                                                |
| Real CI matrix                          | `.github/workflows/ci.yml`: ubuntu/macos/windows × Node 18/20/22, running lint → `prettier --check` → build → `test:coverage` → `test:e2e` on every push and PR.                                                                                                                                                                                  |
| Gated, provenance-signed publishing     | `publish` job needs `test` to pass, verifies the git tag matches `package.json`'s version before running, and publishes with `npm publish --provenance` (`id-token: write`).                                                                                                                                                                      |
| No secrets on argv where avoidable      | `KeychainVault.set`/`SecretToolVault.set` prefer stdin (`src/core/vault.ts`); `DpapiProtector` never puts key material in a PowerShell argument.                                                                                                                                                                                                  |
| Uniform, actionable errors              | Every user-facing failure is a `CliError` (`src/core/errors.ts`) with a `hint` — see `classifyStatus` in `src/providers/router.ts`.                                                                                                                                                                                                               |
| Real retry/backoff, not "try once"      | `RETRYABLE_STATUS`, `MAX_ATTEMPTS = 3`, exponential `backoffFor`, `Retry-After` honored via `retryAfterMs` — all in `src/providers/router.ts`, unit-tested with fake timers in `tests/router-network.test.ts`.                                                                                                                                    |
| Structured, changelog-driven releases   | `@changesets/cli` dev dependency; `CHANGELOG.md` carries a detailed, user-facing "Minor Changes" entry per release (0.10.0 through 0.15.0).                                                                                                                                                                                                       |

## Gaps and their adoption step

| Gap                                                                      | Impact                                                                                                                                                                          | Adoption step                                                                                                                                                                                                         |
| ------------------------------------------------------------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| No `SECURITY.md` in this repo's own root or `.github/`                   | Contributors have no documented vulnerability-disclosure path — ironic, since `src/generate/digest.ts` reads `SECURITY.md` _from target projects_ it scans.                     | Add a root `SECURITY.md` stating the disclosure process; this repo's own `devpilot generate` would then pick it up as a convention signal for its own kit.                                                            |
| No `CODEOWNERS`                                                          | No enforced review routing as the contributor base grows.                                                                                                                       | Add a root `CODEOWNERS` mapping `src/generate/`, `src/core/vault.ts` and `.github/workflows/` to their maintainers.                                                                                                   |
| No dependency-scanning workflow (Dependabot/Renovate) in `.github/`      | Dependency vulnerabilities and staleness (`commander`, `picocolors`, and every dev dependency) are caught manually or not at all.                                               | Add a Dependabot config (`.github/dependabot.yml`) for `npm` with a weekly cadence, scoped to `package.json`.                                                                                                         |
| `src/launcher.ts` excluded from coverage thresholds (`vitest.config.ts`) | ~300 lines of interactive state machine (menu filtering, keypress handling, raw-mode terminal control) carry no unit-test safety net — a deliberate tradeoff, not an oversight. | If regressions in the interactive menu recur, add targeted unit tests for `tokenize()` and `menuPrompt`'s filtering logic (both pure enough to test without a real TTY) rather than removing the exclusion wholesale. |
| `devpilot login` is a stub (`src/commands/update.ts`'s `loginCommand`)   | A registered CLI command with no working implementation; the README already labels it "not available yet."                                                                      | Keep the stub's current honest messaging until Cloud Sync ships; do not let new code assume an authenticated-account layer exists yet.                                                                                |
