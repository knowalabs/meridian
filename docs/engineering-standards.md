The enterprise-grade bar for a published npm CLI in this stack, how Meridian measures against it today, and the concrete adoption step for every gap — sourced from `.meridian/docs/codebase-review.md`'s Maturity & gaps section. Read this before deciding whether something is "good enough to ship" or needs a step first.

## Where the repo already meets the bar

| Standard                    | Evidence                                                                                                                                                                                                                                            |
| --------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Strict type safety          | `tsconfig.json`: `strict`, `noUncheckedIndexedAccess`, `noImplicitOverride`, `noFallthroughCasesInSwitch`; `eslint.config.js`: type-aware `recommendedTypeChecked` plus `no-explicit-any`, `no-floating-promises`, `no-misused-promises` as errors. |
| Test discipline             | Unit + e2e split (`vitest.config.ts` / `vitest.e2e.config.ts`), coverage gated at 70% lines / 60% branches on `src/**/*.ts` (`test:coverage`), e2e spawns the real built binary.                                                                    |
| Multi-platform CI           | `.github/workflows/ci.yml`'s `test` job runs the full chain across 3 OSes × 3 Node versions on every push and PR.                                                                                                                                   |
| Security disclosure process | `SECURITY.md`: private-advisory reporting flow, explicit in-scope/out-of-scope boundary, supported-versions table.                                                                                                                                  |
| Code ownership routing      | `CODEOWNERS` names the exact security-critical surface: `src/core/vault.ts`, `src/generate/artifacts.ts`, `.github/workflows/`, `SECURITY.md`.                                                                                                      |
| Release integrity           | `npm publish --provenance` gated on the git tag matching `package.json`'s version (`.github/workflows/ci.yml`'s `publish` job).                                                                                                                     |
| Changelog discipline        | `@changesets/cli` dev dependency feeding a maintained, per-release `CHANGELOG.md` (not an afterthought — see the detailed `0.1.1`/`0.1.0` entries).                                                                                                 |

## Gaps and their adoption steps

| Gap                                              | Current state                                                                                                                                                                                                                                                                                                  | Adoption step                                                                                                                                                                                       |
| ------------------------------------------------ | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| No dependency-vulnerability scanning in CI       | `.github/workflows/ci.yml`'s `test` job runs lint/format/build/test only; `.github/dependabot.yml` exists in the repo layout but its configured scope was not visible in this review — treat it as unverified, not as coverage.                                                                                | Add an `npm audit --audit-level=high` step to the `test` job, or a dedicated CodeQL workflow; separately confirm what `.github/dependabot.yml` actually scans.                                      |
| Release fragility already caused a real incident | `CHANGELOG.md`'s `0.1.1` entry documents npm silently rewriting `bin.meridian` from `"./dist/index.js"` to `"dist/index.js"` during the `0.1.0` publish, disagreeing with the repository's own `package.json`.                                                                                                 | Add a post-build, pre-tag check (e.g. `npm pack --dry-run` diffed against the committed `package.json`, or a smoke install from the packed tarball) to the `publish` job before `npm publish` runs. |
| Single-maintainer bus factor                     | `CODEOWNERS` routes every path to one owner (`@sonal-sithara`); "Recent activity" shows 1 contributor across 67 commits in the last 180 days.                                                                                                                                                                  | Not fixable by code — track as an organizational risk; when a second maintainer joins, split `CODEOWNERS` so the security-critical surface isn't a single point of failure for review.              |
| `--estimate`'s cost data is thin                 | `MODEL_PRICING` in `src/providers/router.ts` hardcodes exactly two models (`claude-sonnet-5`, `gemini-2.5-flash`); every other provider/model reports "unknown cost" rather than a wrong number (correct fallback behavior, but the README's "Knowing the cost before you spend it" framing outruns the data). | Expand `MODEL_PRICING` for the providers users actually route to, or add an explicit note in README.md's `--estimate` section naming which models have pricing data today.                          |
| `meridian login` is a stub                       | `loginCommand` in `src/commands/update.ts` prints "not available yet" and does nothing else — openly labeled, not hidden.                                                                                                                                                                                      | Keep it labeled until implemented; track its target milestone in [roadmap.md](roadmap.md) rather than letting it sit unlabeled indefinitely.                                                        |
