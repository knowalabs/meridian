# Tech debt

An honest register of known gaps in this repo's own tooling and process, each with its impact and the smallest fix. Read this when deciding what to pick up next, not when evaluating whether the codebase is healthy overall — see [engineering-standards.md](engineering-standards.md) for that framing. Sourced from the Maturity & gaps section of `.devpilot/docs/codebase-review.md`; only gaps visible in this repo's own files, never invented.

| Area                            | Description                                                                                                                                                                        | Impact                                                                                                                                                                                                                                  | Suggested fix                                                                                                                                                                                       |
| ------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Governance docs                 | No `SECURITY.md` or `CODEOWNERS` at the repo root, and none under `.github/` (which currently holds only `workflows/ci.yml` and `copilot-instructions.md`).                        | New contributors have no disclosure path for vulnerabilities and no enforced review routing; this repo's own `raisingTheBar()` heuristic (`src/generate/artifacts.ts`) would flag exactly this absence in any other project it scanned. | Add root `SECURITY.md` and `CODEOWNERS`; both are read by `src/generate/digest.ts`'s digest builder for _target_ projects, so adding them here also lets DevPilot's own generated kit reflect them. |
| Dependency hygiene              | No Dependabot/Renovate config appears in `.github/` — dependency updates for `commander`, `picocolors`, and the dev dependencies (`eslint`, `typescript`, `vitest`, …) are manual. | Security patches and version drift are caught only when someone remembers to check.                                                                                                                                                     | Add `.github/dependabot.yml` for the `npm` ecosystem with a weekly schedule scoped to the repo root.                                                                                                |
| `src/launcher.ts` test coverage | Explicitly excluded from `vitest.config.ts`'s coverage thresholds — a deliberate call, but it means the ~300-line interactive menu/keypress state machine has no unit-test net.    | A regression in `menuPrompt`'s filtering or `tokenize`'s quote-handling would only surface via human testing or e2e, not `npm run test:coverage`.                                                                                       | Add focused unit tests for the pure helpers (`tokenize`, the filtering logic inside `menuPrompt`) without trying to unit-test raw-mode TTY interaction itself.                                      |
| `devpilot login` stub           | `src/commands/update.ts`'s `loginCommand` is registered in `src/cli.ts` but implements no working Cloud Sync — the README states it is "not available yet."                        | A command surface exists with no behavior behind it; any code assuming an authenticated-account layer today would be building on nothing.                                                                                               | No fix needed until Cloud Sync ships — keep the stub's messaging honest and gate new features on the real capability landing, not on the command existing.                                          |
| DPAPI legacy plain-hex fallback | `DpapiProtector.unprotect()` in `src/core/vault.ts` intentionally keeps a fallback to `PlainProtector` for master keys stored before the `dpapi:` prefix existed.                  | Not itself a bug — but it is a permanent piece of backward-compatibility code with no expiry, and a future contributor might "clean it up" without realizing it would break existing users' stored keys.                                | Leave it in place. If ever removed, it must be preceded by a migration path that re-wraps every existing plain key, not a direct deletion.                                                          |
